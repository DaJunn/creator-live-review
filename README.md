# creator-live-review

**带货者单场直播复盘** —— 把一场直播复盘成运营能直接执行的动作。

让 AI agent（DSH / Codex / Claude Code 等）使用。

## 解决什么问题

之前复盘一场直播，看完数据还是不知道该干什么，结论停在「这场 GMV 多少」。

现在能拉出这场（或这天、这个带货者近 N 场）的场次和商品明细，算出 ATV 和公司侧营收，诊断货盘集中度、价格带、场次效率、异常，最后直接落到**谁该做什么**。

## 诊断什么

- **货盘集中度**：Top1 / Top3 占比
- **价格带**：低客单走量 vs 高客单拉 ATV
- **场次效率**：GMV / 小时、单量 / 小时
- **异常**：观看高转化低、单品过度集中、退货/售后风险、未发货风险

## 输出什么

固定格式的内部复盘，**责任到人**：

```
XX 带货者 <日期/场次> 复盘：

结论：
- 这场是：好 / 一般 / 差
- 核心原因：一句话

结果：
- GMV：¥X（友望预估）
- 单量：X 单
- ATV：¥X
- 公司侧营收测算：¥X
- 公司侧毛利润：¥X / 成本未录入

货盘：
- Top1：¥X / X 单 / 商品名 / 占比 X%

问题：
- <问题>：<证据>

下场动作：
- 带货者：<动作>
- 运营：<动作>
- 选品：<动作>

口径：
友望直播数据 + 微信小店订单核对；公司侧营收按默认参数测算；数据截止 <时间>。
```

## 前置依赖

本 skill **没有自己的脚本**，是纯编排层。它调用：

| 依赖 | 用途 | 是否必需 |
|---|---|---|
| `youwant` | 拉场次与商品明细 | **必需** |
| `wechat-store-order-stats` | 订单核对 | 可选 |

> ⚠️ `youwant` 目前**尚未单独发布**。没有它，本 skill 拉不到数据。
> 发布情况以 https://github.com/DaJunn 为准。


## 触发方式

对 agent 说：「复盘 XX 昨天」「XX 这场卖得怎么样」「XX 最近一场直播数据」「给 XX 出下场直播动作」「看 XX 的商品明细/货盘/转化」。

## 默认口径

- 数据源优先级：`youwant` 场次/商品明细 → 微信小店订单 → 人工补充
- 公司侧营收 = GMV × 商品佣金率 × (1 − 退货率) × MCN 分成比例
- 默认参数：商品佣金率 30%、退货率 20%、MCN 分成 40%
- 友望 GMV 与微信订单金额不一致时**分别标注来源，不强行合并**
- 面向内部运营，不写营销文案

## 风格约束

- 统一称「**带货者**」，不写「主播」「达人」
- 不把 GMV 当公司收入
- 缺字段写「未提供」，不编造

## 配套

- 想要**跨场趋势**（哪几场值得研究）用 `wechat-channels-history-review`
- 想要**货架怎么摆**用 `wechat-live-commodity-ops`
